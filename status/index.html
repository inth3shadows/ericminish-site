Projects in progress

Day job

I work on integration and data-pipeline engineering: workflow automation in a CRM (customer relationship management system), services that ingest data, scheduled jobs on managed cloud infrastructure, and reporting from a data warehouse with access control. One of those services uses a language model to score call transcripts against a rubric. Fixed rule-based checks run first, and a person reviews the result afterward, so the model does not make the final decision.

terse

terse is a compression proxy for the output of MCP tools (MCP is the Model Context Protocol, the standard that connects tools to AI agents). It reduces that output by 59 percent, counted in tokens (the units a model reads and is billed by). Whenever it cannot prove the compressed version restores exactly, it forwards the original output unchanged, so no information is lost. Recent work has been on security. Credentials must not be sent along when a request is redirected to another site, and the configuration generator, which tunes settings for speed, may not overwrite a safety setting. Case study.

testgraph

Given a code change, testgraph names the user journeys the change could have broken. It traces a static call graph (a map of which code calls which) instead of reading a test coverage report, so it works on a repository that has never run its tests. It was recently made public and published on PyPI, the Python package index. Current work compares the journeys it selected against what running them found, so its miss rate can be reported as a number. Case study.

harness

harness decides whether a code change written by an AI agent is acceptable, using four fixed checks. No language model takes part in that decision, and nothing is committed automatically afterward. The loop that plans and produces the changes still runs on a runtime I did not write. The current build moves that loop into harness itself and adds tools that can write files, each limited by isolation rules that set what it may reach. Case study.

Knowledge graph

My personal knowledge base runs on the Postgres database. Agents can add to it only by proposing an entry, and every proposal is reviewed before it is saved. This quarter its embeddings (the numeric text representations used for search) moved into a separate service that runs alongside it, which cut the deployed container image from 2.14 GB to 442 MB. It also dropped half its tools, because the size of each tool response mattered more than how many tools there were.

Frostline

Frostline is spatial modeling over fifty thousand Michigan well records, and the contractor-intake business built around it. In these records, location predicts well depth, but it does not predict well yield (how much water a well produces).

Homelab

The homelab is ten machines under Proxmox (a server virtualization platform) that run live routing, monitoring and backups. A workload whose traffic must go through a VPN (virtual private network) is bound to the VPN’s network interface by name, because starting services in the right order does not guarantee that the traffic uses it.
