Agent infrastructure

terse 59% fewer tokens open

MCP, the Model Context Protocol, is the standard that connects tools to AI agents. terse is a proxy that sits in front of MCP tool servers and compresses what they return without losing anything. If it cannot prove that a compressed payload rebuilds the original exactly, it forwards the original unchanged. On a benchmark of nine GitHub API payloads that total 365,144 tokens as raw JSON, the compressed form uses 59% fewer tokens. The project is public under the MIT license, and the repository includes a benchmark harness so you can measure the saving on your own tools.

RunEcho ~12 ms · 0 tokens open

Stops an agent from writing a call to a function your repo does not have, before the edit is saved. It runs as a hook (a step the agent loop triggers automatically) and checks every edit against the functions and other symbols the code declares. Each check takes about 12 ms. It uses no language model, no network and no build, and a passing check adds nothing to the agent’s context. Its accuracy is measured against dated git history. Over 30 days, 406 flagged symbols could be rated: 62 (15.3%) were false positives, 137 (33.7%) were premature (the code was added later), and 207 (51.0%) were references to something that did not exist.

testgraph names journeys at risk open

Given a diff (a set of line changes to the code), it answers which user journeys (user-facing flows through a product, such as “claimant submits a signed form”) the change could have broken, and in what order to test them. Test-impact tools usually answer with a list of tests, and they need coverage data (a record of which code each test ran) from a previous run. testgraph walks a static call graph (a map of which code calls which) backwards from the changed lines, so it works on a repo that has never run its test suite. It is tuned to catch every journey that broke, so it will sometimes flag one that turned out fine.

harness 4 mechanical checks private

A harness for coding agents, built for a single developer, in two parts. The first is a gate that gives a fixed-rule verdict on a code change. It runs four checks that keep no state: the test suite, a symbol contract (which fails when a change leaves its declared scope or removes a symbol without opting in), a scan for staged secrets, and a scan for reachable vulnerabilities (ones the project’s code can trigger, as opposed to ones that are only listed). A pass leaves the branch for a human to commit. Nothing is committed automatically, and no language model makes the judgment. The second part is a runtime that assigns a model to each role (consult, scout, builder, reviewer or scribe) and runs the loop of request, tool call and result against read-only tools. It cannot yet edit files or run commands.

Measurement

modelbench cost per solved task private

A personal benchmark that takes bug-fix commits from my own repositories and replays them against lower-cost models, three times per model by default, so a gap between two models can be told apart from noise. Its headline figure is cost per solved task. In one comparison of fifteen tasks, the small tier (Claude Haiku) solved 10 at $0.51 per solved task, and the large tier (Claude Opus) solved 15 at $2.09. It also publishes its own corrections: one defective task had made all three tiers look worse than they were, and four published claims were corrected.

flight-recorder 11,179 sessions scored private

Scores each coding-agent session on two things, kept separate: what it cost, from the transcript, and how much of its code was still in the repository when it was last scored, from git. A session is re-scored until it is seven days old. It has scored 11,179 sessions. Every average comes with a 95% confidence interval (a range that shows how precise the average is), and models are compared only on similar work, so a hard repository does not make a model look weak.

Lodestone 5 of 10 at full scale open

Local retrieval over my own notes: Claude Code session transcripts, a ChatGPT export, planning documents and repository markdown. The notes are split into chunks (short passages of text). Semantic search (matching by meaning) beat keyword search on a 1,222-chunk development set and lost to it on the full collection of 57,562 chunks, and the write-up starts with that result. On the development set’s seven paraphrased questions, semantic search scored 0.731 nDCG@10 (a ranking score, higher is better) against 0.436 for keyword search. On ten test questions asked against the full collection, the default setup returned something useful in its top three results for five. The experiment set a kill gate in advance (a stated condition for stopping the project). The re-ranker passed it, so the project continued. It also used negative controls (cases where the right answer is known to be nothing) and blind judging of pooled results, where results are graded without the judge knowing which method returned them.

Frostline 50,083 well records open

Spatial models over the public Michigan well record. Depth is predictable from location because nearby wells have similar depths. Moran’s I measures how strongly nearby wells resemble each other: near 0 means no spatial pattern, and higher values mean a stronger one. It is 0.393 for depth and 0.089 for yield. The aquifer interval (the top and bottom depths of the water-bearing layer) looked like a promising target and was dropped: against a baseline computed from well depth, it was about 96% a restatement of depth.

Origin Sentinel read-only first, then repairs open

Checks the health of services reached through a tunnel (a Cloudflare connection that exposes a machine without opening ports). It catches the failure where the public edge looks healthy but the service behind it is down. It first shipped without write access, and it was given the ability to fix problems once its classifications held up in the field.

Multi-provider LLM gateway cost tracked against a budget open

Routes one coding agent across several large language model (LLM) providers by task, and tracks cost against a budget as it accrues. Secrets are kept out of the environment: keys are pulled from a secret broker at process start and held only in memory.

Knowledge base for agents 92.0% of 238 proposals accepted private

Long-term memory for my coding agents. Agents can only propose a fact; an AI reviewer approves, edits or rejects each proposal before it is stored. Over the last 30 days the reviewer accepted 92.0% of 238 decided proposals. On hand-built vague rules it caught 63.0% of the short ones and 27.8% of the long ones, and the write-up measures that weakness alongside the search quality.

secret-broker 2,568 receipts, chain intact private

A local MCP server (MCP is the standard that connects tools to AI agents) that lets coding agents use credentials without receiving them. Every call writes a hash-chained receipt, so a later edit to the log is detectable; 2,568 receipts over six months verify intact. Entropy-based secret detection caught 5 of 13 of the broker's own credentials and flagged 566 harmless tokens on one clean response before it was fixed.

codegraph correctness 111 issues filed, 17 PRs merged open

Checks codegraph, an open-source code-intelligence tool, against compiler type checkers and against freshly built indexes, and reports the differences upstream. 111 issues filed, 81 closed as completed by the maintainer, and 17 of my pull requests merged. A replay of 2,979 index updates found 12 places where the updated index differed from a fresh one.

The terminal

My whole working environment is a browser tab. A terminal multiplexer (a program that keeps shell sessions running and lets several screens attach to them) runs on a machine at home. A small web terminal serves it, and an identity-proxied tunnel (a tunnel that checks who you are before any traffic reaches the machine) publishes it. No port is open to the internet, and no session starts without single sign-on. Opening the same address from a phone, a laptop or a borrowed machine attaches to the same live session, so work carries over between devices.
