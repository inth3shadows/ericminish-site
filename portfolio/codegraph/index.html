Checking codegraph’s call graph against compilers and fresh indexes

codegraph is an open-source tool (MIT licensed, about 76,000 GitHub stars) that indexes a codebase into a call graph, a map of which functions call which, and serves it to coding agents over MCP (Model Context Protocol, the standard way agents call tools). I use it every day and build other tools on it. I wrote test tooling that compares its graph with independent references, reduced each disagreement to a minimal repro (the smallest code that shows the bug), and filed it upstream, with a fix when I had one.

What it is: a public fork with fixes for wrong call edges, private test tooling, and codeshot, a public diagram tool built on the graph.

Why a wrong call edge is worse than a missing one

An edge is one link in the call graph, from a call site to the definition it reaches. When codegraph cannot tell which same-named function a call reaches, it can guess by name. A missing edge leaves a visible gap. A wrong guess looks like every correct edge, so an agent asking “who calls this?” gets a confident wrong answer.

In October I audited codegraph against each language’s type checker on my own repositories. Precision (the share of reported edges that were correct) was 99.8% for Python calls, 97 to 100% for TypeScript and 97.8% for Go, where recall (the share of true calls it found) was 98.1%. The remaining errors look like every other edge, and finding them takes a reference that does not come from codegraph.

Three checks that do not trust the graph

Each check compares codegraph with something it does not control.

Compiler oracle joined per call site

SCIP is a code index format from Sourcegraph whose indexers run each language’s own type checker (tsc, pyright, javac) and record where every reference resolves. The oracle joins codegraph’s edges to SCIP’s references by file, line, called name and nearest column, so overloads and same-named methods stay separate.

Each disagreement is sorted by cause. Three buckets hold bug candidates: the compiler resolves a different project definition, resolves a library where codegraph linked a project function, or sees a local variable where codegraph linked a global. Other buckets hold codegraph’s deliberate conventions. On jsoup, a public Java library, 16.9k call sites agreed and 2.4k fell in the wrong-target bucket. Triage found three candidate shapes, and one reproduced minimally (#3040).

Sync-versus-fresh replay 7 replay lanes

codegraph updates its index incrementally when files change (a sync). The harness replays a repository’s git history, syncs after each step, and compares the result with a fresh index of the same commit. Seven lanes vary the replay: no-op, forward, reverse, random jumps, one file at a time, a sync killed mid-write, and two syncs at once.

A disagreement triggers a second fresh build, so nondeterminism is not reported as drift. A control run with sync switched off, which must show drift, was caught on 4 of 4 forward steps, 4 of 4 reverse and 7 of 8 file by file. The overnight run on 29 October covered 11 repositories: 2,979 steps, 12 drifts and no failed integrity checks. One drift was a harness fault, and the harness now guards against it.

Fault injection 2 daemon bugs

Two bugs in codegraph’s daemon and worker pool depended on timing: a peer that drops mid-handshake leaves a phantom client that keeps the daemon from exiting, and a worker that fails to open its database stays in the pool and errors on every call. Each harness drives codegraph’s own classes in one process, forces the failure at a chosen point beside a control arm, and prints PROVEN or not reproduced, with no timing race. Both issues (#1356, #1357) were closed as completed on 27 September.

Each finding was reproduced on current upstream code in a minimal fixture and checked for duplicates before filing. On 29 October I re-checked all 41 then-open issues against upstream (39 by fixture, 2 by reading the code), and none had been fixed without notice.

Fixes that were stopped or parked

  1. An aliased-import fix contradicted upstream policy. An import of a name the module lacks, such as from .s import ARMS as LEAK, bound to any project symbol named like the alias. My fix failed two upstream tests that encode the opposite behaviour on purpose, so I dropped it and drafted an issue instead.
  2. A Python typed-receiver exception added wrong edges. For #2583, its pattern-based receiver typing missed imports and rebinding and linked standard-library classes to project classes. I parked it and posted the findings. The maintainer later closed the issue as completed.
  3. An object-member sync fix was parked after several redesigns. Its issue, #3015, is still open with no pull request.

codeshot: diagrams that fail CI when the code changes

codeshot reads codegraph’s index and draws architecture and call diagrams into a repository’s documentation. --check exits with code 1 when a committed diagram no longer matches the code, and --forbid 'src/ui/->src/db/' exits 1 when a file dependency crosses a forbidden boundary. It compares graph structure (nodes and edges) instead of SVG bytes, so different graphviz versions agree.

Against npm codegraph 1.5.0, a callee query for a name defined in two files returned both definitions’ callees, so a two-file fixture drew 4 edges where 2 existed. codeshot re-queries such names per file and discards answers it cannot trust, such as a list codegraph cut off at 12 entries for a function with 23 callees. It then falls back to the broader query and names each affected symbol in a warning.

Reading codegraph’s SQLite index directly, in place of about 130 sequential CLI calls, cut an architecture scan of codeshot’s own repository from 48.7 s to 1.3 s. With its one intended difference switched off, the direct read drew byte-identical diagrams to the CLI path on five test targets. The suite reports 195 passed and 0 failed (3 November 2026). It has no measured catches in other people’s repositories yet. Of its six CI failures, four were its own diagram check failing on development branches.

What the checks do not cover

  • The oracle checks only edges codegraph resolved, so calls it misses entirely are not reported.
  • scip-typescript sees only the files a tsconfig includes, and f-string and template-literal calls often fail to line up. scip-java 0.12.3 does not load under Kotlin 2.x, so there is no Kotlin data.
  • Five new candidate shapes found on 3 November are drafted and not filed. One is a limit already stated in an earlier pull request of mine.
  • The tooling is private and has paths hard-coded to my machine. The fork is built from source and is not on npm.
