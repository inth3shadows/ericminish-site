Stopping a call to a function that does not exist

RunEcho checks every edit a coding agent is about to write against the symbols (function, type and constant names) that your code declares, and stops edits that reference a symbol that does not exist. It covers one kind of mistake with one cheap check.

What it is — a pre-write hook (a script the agent runs automatically before each file write), plus the deterministic symbol index behind it.

Status — public, MIT. Go, with a bundled copy of the tree-sitter runtime (a parsing library). Windows, macOS and Linux.

A deterministic check: same input, same answer

Every check parses the code and looks the names up in an index. The same code gives the same answer on every run, machine and agent, because no model is involved. It needs no API keys, network, build or language server.

A clean check costs zero context tokens (tokens are the units a model reads and is billed for). It writes nothing unless it stops an edit, and then about a hundred tokens. Because it runs as a hook, the agent spends no context deciding whether to call it. The companion server, which answers structural questions about the code on demand, is a separate piece and does cost context: its tool schemas take around 968 tokens at session start. Both figures are published in the repository.

How often it is wrong, and how that was measured

The first idea was to count how often the user overrides the guard. That gave nothing to measure: across thirty days of traffic, all 308 gated edits were approved and none were denied. A rate from that would have called the guard perfect while only reflecting the user’s willingness to approve.

So each flagged symbol is judged against dated git history: whether it was defined when the guard objected, and whether it is defined now.

The 51% is a share of the flagged edits only, so it says nothing about how much of an agent’s output is hallucinated.

What RunEcho checks and what it misses

RunEcho reads unqualified references, meaning names used on their own: bare function calls, constant references and type annotations. It was tested on a corpus of model hallucinations taken from live session transcripts: fifteen hand-verified cases, each confirmed by a compiler or runtime error. Nine of the fifteen are hallucinated names, and it catches four of those nine.

The other five are qualified references, where a name hangs off an object: df.groupby(…), tree.Root(). Resolving those needs receiver-type inference (working out what type the object on the left is), a semantic analysis RunEcho does not do. The index covers more languages than the guard checks: shell, Rust and Ruby feed the index but are not validated at edit time.

Use it the way you use a type checker: one layer that removes one class of mistake, next to the tests and review that catch the rest.

A design dropped after using RunEcho on its own development

An edit-scope contract declares what a piece of work is allowed to touch, so the guard can object when an agent edits outside it. The planned next step was to bind a contract automatically when a session starts. Using the guard on its own development, on the day it merged, ended that plan: the contract went stale within the same session, at the moment the work it described was merged.

A session often spans several unrelated pieces of work. A contract belongs to a task. Between tasks the right state is no active contract: the guard costs nothing, says nothing and abstains. Binding a contract per session would leave the guard enforcing an outdated scope, which produces wrong flags and wrong passes.

Choosing a parser by what a shortcut would get wrong

Each language gets a parser chosen by one test: whether it contains constructs that a cheap masker cannot tell apart without parsing. A masker blanks out strings and comments while keeping character positions, so a regex can search the rest. Languages that fail the test get a full tree-sitter grammar (a parser that builds a syntax tree); the others use regex plus a masker.

Ambiguity is the right test because of how a masker fails. If it guesses wrong, it fails silently and loses every symbol after the mistake. The result looks the same as a file with no symbols, which is the worst failure for a guard. In Rust, 'a is a lifetime in one line and a character literal in the next, and only parsing tells them apart.

Visibility rules follow from the language. Go extracts only exported (capitalised) names, because an unexported Go name cannot be referenced from outside its package. Rust extracts everything, because a reference to a private function from elsewhere in the same crate is ordinary, and filtering it out would miss the common case.

Reducing false alarms and per-edit cost

Duplicate-symbol warningsBuild-constraint pairs (the same function defined once per platform) produced 91% false positives. Suppressing the warning only when both files carry a build constraint removed all of them without calling out to the Go toolchain. A pair with one constrained and one unconstrained file still warns.
Store accessChecking the contract meant opening the store a second time, measured at +9.5 ms per edit. Sharing the handle with the symbol lookup that was already running brought it down to +0.36 ms.
Threat modelRunEcho runs locally behind a firewall, so it has no web attack surface. The binaries are distributed publicly, so the release pipeline is in scope; authentication and rate limiting are not.
