Why It Matters

What the lab is actually for

The useful part is not the node count. It is clear separation between boxes, services, and public surfaces, so a change is easy to reason about and a failure is easy to isolate.

It is also where the quiet failures happen. One service spent weeks returning nothing because its config pinned an IP address the machine no longer held — everything was up, nothing was broken, and the results were simply empty. The fix was to stop referring to that machine by number at all. A workload sharing a VPN sidecar taught the same lesson: binding it to the tunnel interface by name is a control, and restarting things in the right order is only a habit that works until it doesn't.

Uptime Kuma is the monitoring piece I most want to surface here. A better next version of this page would turn the hardware/status block above into a real status view instead of a static sketch.
