# Technical Reference: ericminish-site

## Architecture

A hand-written static site with no framework or browser JavaScript. Python
helpers generate the writing files and charts; the deploy job refreshes the
contribution strip before copying the static files to the server.

```
repo (git)
  └── copy ──▶ self-hosted container
                  └── Docker + Caddy ──▶ live document root
                        └── Cloudflare ──▶ ericminish.com
```

Every page is a complete HTML document that repeats the same header, nav, and
footer markup inline. The site has 27 HTML pages. A nav change requires an
edit across every page; `tools/check-pages.py` fails if one page's nav differs. Python helpers generate the writing index, Atom feed,
sitemap entries, reading times, charts and contribution strip before deployment;
visitors receive static HTML and CSS.

All styling lives in one stylesheet, `assets/site.css`, linked with a manual
cache-busting query string. Both typefaces are self-hosted from
`assets/fonts/` — there is no third-party request on page load. Pages carry the class vocabulary that stylesheet
defines (`shell`, `hero`, `section`, `panel`, `prose`, `project-card`,
`code-window`, `timeline`, `note`); adding a page means reusing those classes
rather than writing new CSS.

Warns on age (45 days, day job 90), more than 10 PRs merged since a card's date, 60 days without activity, or a repo with 8+ merged PRs in 30 days and no card. `--issue` keeps one issue, "Now page needs an update", in step; it never shows private repo names without a card or private PR titles. ## API Integrations

None. The site makes no outbound requests at runtime and has no backend, no
forms, and no analytics. The web server sends a Content-Security-Policy that allows scripts, styles, fonts and images only from the site itself (inline `style=` attributes are allowed), plus HSTS, `nosniff`, a referrer policy and a permissions policy; the Caddyfile is on the host, not in this repo. Contact happens through a `mailto:` link.

## Configuration

The served pages have no runtime environment variables or config files.
Deployment settings are supplied privately to the workstation job. Two values
that affect the served pages are inline in the HTML:

- **Stylesheet cache-bust** — the `?v=` query on the `assets/site.css` link,
  derived from the stylesheet's own hash. Run `python tools/bump-cachebust.py`
  after any CSS change and before deploying.
- **Contact address** — `hi@ericminish.com`, repeated in every page footer and
  closing line.

Typography follows one rule: **Newsreader argues, Azeret Mono measures**, and
the two are never mixed inside a sentence.

## Deployment

Per `README.md`:

Host details and the full runbook live in the private homelab knowledge base
(`host-ericminish.com`).

1. Back up the current live tree.
2. Copy this repo's site contents *into* the live document root. Never swap
   the directory: Caddy's bind mount follows the inode, and a swap 404s every path.
3. Verify inside the container at `http://127.0.0.1:8080`.
4. Verify publicly at `ericminish.com`.

Rollback is restoring the backup taken in step 1 — there is no build artifact
to revert, only files.

## Maintenance Commands

Before a deploy, check generated writing files and internal links, lint the copy,
and check the Now page:

```bash
python3 tools/gen-writing.py --check
python3 tools/lint-copy.py
python3 tools/gen-now.py --check
python3 -m unittest tools/test_gen_now.py
python3 -m unittest tools/test_draft_now.py
```

Also check tag balance and nav consistency across every page:

```bash
python3 tools/check-pages.py
```

CI (`.github/workflows/check.yml`) runs all of these except `gen-now.py --check`,
which needs the GitHub API, on every pull request.

## Known Limitations

- **The resume PDF is content-addressed.** `tools/make-resume-pdf.py` names it
  `eric-minish-resume-<hash>.pdf`, deletes the previous one, and rewrites the
  link. The visitor still saves it as `Eric-Minish-Resume.pdf` via the
  `download` attribute. Cloudflare served a stale copy once before this.
- **The cache-bust is derived, not typed.** `tools/bump-cachebust.py` hashes
  `assets/site.css` and rewrites the `?v=` query on every page. It must be run
  before a deploy — nothing runs it automatically, and shipping a stylesheet
  change behind a stale query served three rounds of CSS work to nobody.
- **Header, nav, and footer are duplicated in every file.** A nav change is a
  mechanical edit across all pages. `tools/check-pages.py` (CI) fails when
  one page's nav differs from the rest; footers vary by page on purpose and
  are not checked.
- **Dated pages rot silently.** `homelab/` and `status/` both state a
  last-updated month in their own copy. Nothing checks whether that date is
  still honest — it went three months stale before anyone noticed.
- **The homelab node table is hand-maintained**, not live data. It says so on
  the page. Uptime Kuma holds the real state; nothing pipes it here yet.
- **Contribution updates depend on the workstation.** A daily systemd user
  timer runs `tools/regen-deploy.sh` there. It fetches `origin/main`, regenerates
  the strip, checks writing freshness and internal links, and copies the site
  into the existing live root. If the workstation or job is unavailable,
  updates wait. The job checks the public home page's status and capture date;
  it does not verify every deployed file. Host settings remain private.
  `tools/check-live.py` emails once a day when `/build.txt` is more than 26
  hours old. It runs on the same workstation, so if the workstation is off
  nothing alerts.
