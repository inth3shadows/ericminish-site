What installed skills cost in context

Anthropic says you can install many Claude Code skills without context penalty, at about 100 tokens each. I checked that against five months of my own transcripts.

By Eric Minish Published 3 November 2026 7 min read

Result. The per-skill figure holds. The median entry in my skill listing is about 113 tokens, against the documented 100. The total is not free. My latest listing has 50 skills and about 6,660 tokens, every session that recorded a listing carried it, the median listing grew 72% from July to October (13,116 to 22,549 characters), and 18 of the 50 skills were never invoked. A second finding: 34 of 1,076 loaded skill bodies were over the documented 5,000 tokens, and they hold 64% of all the text loaded.

Data. 4,278 session transcripts and 7,091 subagent transcripts from one machine, June to early November 2026. Token figures are characters divided by four. I did not measure cost after caching or whether any skill improved results.

The claim I tested #

A skill in Claude Code is a folder with a SKILL.md file of instructions for one kind of task. At the start of a session, Claude Code puts a listing in the prompt: the name and a short description of every installed skill. The full text of SKILL.md, called the body, loads only when the skill is used. The context window is the text the model reads on each request. A token is a unit of text, roughly four characters of English.

Anthropic’s overview of Agent Skills says: “you can install many Skills without context penalty: until a Skill is triggered, only its name and description occupy context.” Its table gives the listing level as “~100 tokens per Skill” and the body as “Under 5k tokens”. The Claude Code page on skills says: “Every skill in the skill listing adds to your context on every turn, whether or not Claude ever uses it.” Both quotes were on those pages on 3 November 2026. I checked the per-skill figure, the total, and whether bodies stay under 5,000 tokens.

Cost of one skill #

The most recent listing in my transcripts has 50 skills and 26,635 characters, about 6,660 tokens. The median entry is 451 characters, about 113 tokens. The mean is 532 characters, about 133 tokens. The documented 100 tokens is close to the median. Fifty skills at 100 tokens would be 5,000 tokens; the measured total is 6,660, 33% higher, because the mean is above the median.

One estimate of mine was too low. In July I planned to replace an always-loaded 25,184-character file of machine notes (about 6,296 tokens) with a skill, and wrote that a skill would take it to “~50” tokens. The skill’s listing entry is 543 characters, about 136 tokens, 2.7 times my estimate. The change still saved space: the body is about 680 tokens and loaded 24 times, where the file had been in every session.

Cost of the whole listing #

Of 4,278 session transcripts, 2,157 recorded a listing at session start. A few recorded more than one, for 2,200 listings in all. Every one of them carried the full listing: the smallest was 5,849 characters (about 1,460 tokens) and the largest 26,635. I did not check why the other 2,121 transcripts have none. Added up, the 2,200 listings are 30.97 million characters, about 7.7 million tokens, one copy per session start.

That counts context space and overstates the money. If the listing is cached after the first turn, later turns read it at the lower cache price. In the weights I use for my usage limit (see my previous post), a cache read counts 0 and a fresh input token 0.94. I did not measure the listing’s cache cost. The listing does take about 6,660 tokens of context before I type anything.

From July to October the median listing grew by 9,433 characters, or 72%, while the median skill count grew from 31 to 44, or 42%. At the October median, 9 of the 44 skills carry the prefix anthropic-skills:, which no July listing had, and the count of other skills rose from 31 to 35. The 13 entries with that prefix in the latest listing average 730 characters each, against 462 for the other 37. I left November out: its 104 listings have a median of 6,850 characters and 14 skills, and I did not work out why.

Skills never invoked #

I counted a skill as invoked if Claude called it through the Skill tool or I typed it as a slash command. Of the 50 skills in the latest listing, 32 were invoked at least once between June and 3 November. The other 18 were not.

The 18 never-invoked entries are 9,737 characters, 36.6% of the listing, about 2,430 tokens. The skills were not all listed for five months. Four of the unused anthropic-skills: entries first appear in October and appear in 191 listings. The other eight first appear in September and appear in 262 to 468 listings. Four unused built-in skills (init, simplify, keybindings-help and fewer-permission-prompts) appear in all 2,200 listings, and together they are 694 characters, about 174 tokens. So five months applies to a few skills, and those are small. One was called seven times under its bare name (deep-research), so by name 17 are unused.

A forked skill runs in its own context, so its body stays out of the main conversation. Of the 1,076 loaded bodies, 1,042 (97%) were 20,000 characters or fewer, which is the documented 5,000 tokens. Those have a median of 4,726 characters (about 1,180 tokens), a 90th percentile of 9,854 (about 2,460) and a largest of 16,627 (about 4,160). The other 34 bodies, 3.2% of loads, were bigger.

The largest SKILL.md among my own 21 installed skills is 14,988 bytes (343 lines), under the 500 lines the docs recommend. Also, 599 of the 4,278 session transcripts (14%) loaded at least one skill body, while all 2,157 transcripts that recorded a listing carried it.

Method and limits #

A script read the transcripts Claude Code writes to disk (11,369 files) and kept only counts and lengths, never message text. Listings come from the skill-listing record at session start, skill calls from Skill tool uses matched to their results, and typed slash commands from the command-name tag. Calls are counted once per call ID, because resumed sessions copy history. These are counts from my machine, not samples of a larger population, so I give no confidence intervals. The limits, largest first:

  1. No outcome comparison. I measured space and did not measure benefit. I do not know whether any skill made a session better, or whether the 18 unused skills would have been called with different descriptions.
  2. Token figures are characters divided by four. They are not billed counts, and code splits into tokens differently from English.
  3. Cache cost was not measured. The listing is probably cached after the first turn, which would lower its price below what its size suggests.
  4. One person, one setup. The sessions include automated runs, entry sizes come from one snapshot, and listings vary by project.
  5. Invocation is narrowly defined. A skill read some other way, such as opening its file, would show as unused. The Claude Code page says the listing is limited to 1% of the context window and drops descriptions of the least-used skills on overflow. I did not check whether that shortened any listing.

What I changed and what is open #

My records show one change, the July move of the machine notes into a skill described above. It came before these measurements. The skill costs about 136 tokens in the listing against 6,296 for the file it replaced.

What is open is whether the 18 unused entries, about 2,430 tokens, are worth their space. Answering it takes the comparison the best-practices page recommends: “Measure Claude’s performance without the Skill”, on tasks each skill is meant for, with a record of whether the skill fired at all. The Claude Code page also describes /skill-doctor, which reports each skill’s cost and use. This post covers the cost side of the question.
