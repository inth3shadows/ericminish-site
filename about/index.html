About

I build infrastructure for AI agents and the data work that runs on that infrastructure. I came to this work from operations. I live in Central Lake, Michigan.

I work on systems where task ownership, status or completion is unclear, and I make them clear.

My design rule

A system should report only what it can check, and say so when it cannot check something. Following that rule has a cost each time. These four projects show how I apply it and what it cost.

Lodestone, a search engineThe search engine I built beat keyword search when tested on 1,271 documents and lost to it when tested on 57,500 documents. The case study reports the loss first.
Frostline, a well-depth modelIn this well-depth model, one candidate prediction target scored 38.8% better than its baseline. Measured against the right baseline, the target only repeated a variable the model already had, so I dropped it.
terse, a compression proxyThis compression proxy sits between my AI agent and the servers that run its tools. When it cannot prove that the compressed output decodes back exactly, it sends the original, uncompressed output. Sending the original is slower, but the agent never receives a damaged copy.
kb, an agent knowledge baseThis knowledge base for AI agents accepts proposed entries from agents and reviews each one before saving it. Saving everything unreviewed was the cheaper option. I rejected it because past about 2,000 entries the important ones became hard to find.

Background

My professional work has been in operational systems: tracking the state of workflows, handling events, automating CRM (customer relationship management) processes, and building the reports that show afterwards what happened.

AI agents need the same things: a record of what they did and a defined response when a step fails. An agent acts on information it cannot check directly, so most of my work on agents is deciding what an agent may read, what it may change, and what happens when one of those steps fails.

I run these systems on my homelab, ten machines of my own that handle routing, monitoring and recovery, and I test how the systems fail on that hardware.
